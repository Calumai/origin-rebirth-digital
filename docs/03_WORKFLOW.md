# 03 執行流程

## 核心原則

人類掌舵，AI 執行。人類負責文化正確性、授權、商業承諾與最後品味；AI 負責盤點、原型、實作、測試、文件與缺口標示。

4. 記錄本次可修改檔案與保護檔案。
5. 建立改動前基準：語法、模擬、主要流程與必要截圖。

## 1. 內容與文化盤點

產出文化清冊，每一項至少包含：

- 內容 ID、族群、類型、目前文案與顯示位置。
- 來源網址／出版品／提供者。
- 圖像、音樂、文字與名稱的權利狀態。
- 審校人、審校日期與意見。
- 狀態：待查、待審、待授權、可原型、可商用。

完成條件：沒有一筆文化內容只寫「網路資料」或「AI 生成」。

## 2. 資訊架構與灰盒

先畫流程與畫面層級，不先做裝飾：

- 首頁：價值、玩法證明、CTA、族群／文化、商業資訊。
- 故事：核心循環、經審文化卡、來源與延伸閱讀。
- 設定／大廳：名稱、人數、族群、房號與狀態。
- 牌桌：當前目標、家屋、手牌、建議行動。
- 結算：勝負、策略回顧、文化回顧、再玩。

完成條件：桌機與手機灰盒都能走完整主要流程。

## 3. 設計系統

1. 把色彩、字體、間距、圓角、陰影、層級與動態寫成 token。
2. 建立 button、card、panel、modal、progress、tooltip、toast 狀態。
3. 套用 Variance 8／Motion 7／Density 5。
4. 做一張首頁與一張牌桌視覺樣板，交人類確認方向。

完成條件：相同狀態不再由不同頁面各自發明。

## 4. 分階段實作

順序：

1. 首頁與故事頁。
2. 設定頁與連線大廳。
3. 牌桌資訊層級與行動抽屜。
4. 卡牌、素材、家屋與事件回饋。
5. 結算與商業資訊。
6. 鍵盤、reduced-motion、錯誤與離線狀態。
7. 資產壓縮、metadata 與發布準備。

每階段：

- 只修改工作單列出的檔案。
- 改完立刻做該畫面煙霧測試。
- 保存桌機與手機截圖。
- 更新 CHANGELOG 與 TASKS。

## 5. 文化關卡

任何文化內容進入正式畫面前：

1. AI 整理來源與疑點。
2. 人類確認使用目的與權利。
3. 對應族群審校。
4. 修訂並記錄版本。
5. 明確標記可商用範圍。

若未完成第 2–5 步，只能使用「待審原型」狀態，不得發布成商業宣稱。

- 桌機 1440×900 與手機 390×844 走主要流程。
- Console 0 uncaught error。
- 本機資產 404 為 0。
- 對修改的互動做鍵盤與 reduced-motion 檢查。

發版前執行 TESTING.md 全矩陣。

## 7. 獨立驗收

實作者完成後，交給 fresh-context reviewer：

- 只提供客觀背景與驗收條件，不先透露期望判定。
- reviewer 需 read-back、實跑或截圖比較。
- FAIL 時列出最小修正，不直接掩蓋問題。
- 同一方案兩輪仍失敗就停止，換方案或請人決定。

## 8. 人類必須拍板的節點

- 品牌 Logo、主視覺與最終品味。
- 是否保留現有角色、背景與音樂。
- 文化內容正確性、審校人與授權。
- 平台、價格、年齡、遊戲時間、發行狀態。
- 正式部署、網域、分析追蹤、隱私與連線服務。

## 11. STEAM 教案內容進入流程

1. 先以遊戲卡面作為「觀察物」，只描述畫面中可見的形狀、材料標籤與遊戲數值。
2. 將學生提出的因果解釋標記為「假設」，安排可操作的模型測試，不直接升格為文化事實。
3. 氣候背景只引用國教院、中央氣象署等可追溯官方資料。
4. 若要加入特定族群的家屋、材料、環境適應或知識體系，建立獨立內容項目並附來源、權利狀態、審校者及審校日期。
5. 只有 `review.status = approved` 且必要欄位齊全的文化內容，才可進入正式隨機池。
6. 每次新增學段、主題或內容模板後，執行全部教案組合測試與人工列印檢查。

### 教師試教回饋欄位

- 學段、班級人數與實際耗時。
- 學生能否分辨觀察、推測與來源證實。
- 材料是否可取得，測試是否安全且能在時限內完成。
- 哪一個步驟最容易卡住，以及需要的差異化支持。
- 文化表述是否需要顧問重審。
- 下一版修改與負責人。
